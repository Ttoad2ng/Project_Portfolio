# Project 04. 사출 공정 품질 예측 및 모니터링

[전체 포트폴리오](../README.md)

공정조건만으로 설명하기 어려운 품질 변동을 확인하고, 과거 품질이력 기반 조기 경보 문제로 재정의했습니다.
**제품 행 단위 HGB 분류**와 **Shot 단위 Ridge 기준선**을 별도 트랙으로 검증하고 Streamlit 화면으로 구현했습니다.

## 문제 재정의

공정조건 단독 분류모델은 ROC-AUC **0.496**을 기록했습니다.
동일 Shot의 공정변수 9종이 같아도 PASS·FAIL이 함께 나타나는 Shot이 **58%**로 관찰되었습니다.
이에 AOI·FAI·장비/cavity의 과거 상태를 예측시점 이전 정보로 생성하는 품질이력 모델로 분석을 확장했습니다.

## 트랙 1. 제품 행 단위 품질이력 HGB

학습, 확률 보정, 임계값 선택, 최종 평가 구간을 시간 순서대로 분리했습니다.

| 단계 | 포트폴리오의 구간 |
|---|---|
| Train | 7–10월 |
| Calibration | 11월 |
| Threshold | 12월 |
| Test | 다음 해 1–2월 |

| Test ROC-AUC | Recall | Precision | FPR |
|---|---|---|---|
| **0.7854** | **71.78%** | **86.70%** | **28.94%** |

공정조건 단독 모델과 품질이력 모델의 보고된 AUC 차이는 0.2894입니다.
경보 정책 미적용 행은 0%였지만, 이는 불량을 모두 탐지했다는 의미가 아닙니다.
FPR과 설비별 성능 차이를 운영 단계에서 지속적으로 점검해야 합니다.

## 트랙 2. Shot 단위 Ridge 기준선

| 항목 | 결과 |
|---|---|
| Pooled MAE | **0.4137** |
| 2월 MAE | **약 0.468** |
| Historical replay | **22,407 Shots** |

Ridge는 공정조건 기반 Shot 단위 기준선과 대시보드 시연에 사용했습니다.
HGB와 Ridge는 **분석 단위·입력·평가지표가 다르므로** AUC와 MAE를 같은 성능 척도로 비교하지 않습니다.
Historical replay는 과거 데이터를 재생하는 운영 시연이며 신규 생산 데이터에 대한 독립 검증과 구분합니다.

## 대시보드 기능

- Shot 흐름의 Play / Pause / Reset 제어
- Normal / Warning / Watch / Critical의 4단계 상태 표시
- 공정조건 추이, 설비별 비교, 공정 이력 확인
- 선택 Shot의 9개 공정조건과 선형 점수 기여 방향 확인
- 관리한계 기반 상태 표시와 점검 가이드 제공

## 검증과 해석

전처리 파라미터는 학습 구간에서 산출하고, 특징은 예측시점 이전에 이용 가능한 정보로 구성했습니다.
평가 대상의 사후 검사 결과가 입력에 포함되지 않도록 과거 이력과 예측 타깃을 분리했습니다.
동일 타임스탬프 Shot은 함께 공개해 replay 과정의 부분 노출을 통제했습니다.

AOI 선별 모집단에서 얻은 예측값을 전체 생산 불량률로 해석할 수 없습니다.
설비와 품번의 구조적 연관으로 개별 요인의 인과적 효과를 분리하는 데도 한계가 있습니다.
실제 운영 적용 전에는 검사 결과 확정 시점을 명확히 하고 신규 기간에서 독립 검증해야 합니다.
